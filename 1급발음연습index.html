# 1급 개인 발음형 페이지 재생성 프롬프트 공통 구현 계약을 적용해 `pronunciation.html`을 구현하라. 이 페이지의 핵심은 짧은 카페 주문 문장을 `듣기 → 말하기 또는 직접 입력 → 즉시 완성도 피드백 → 다음 문장` 순서로 네 번 연습하는 것이다. ## 1. 고정 문서와 첫 화면 문구 - 파일명: `pronunciation.html` - ``: `한국어로 인사하기 | 개인 발음형` - 상단 바 오른쪽 텍스트: `개인 발음형` - 배지: `1급 1과 · 안녕하세요` - h1: `듣고 같은 문장을 말해요` - 지시: `먼저 문장을 듣고, 마이크나 직접 입력으로 연습하세요.` - 저장 pageId: `pronunciation` - 실제 localStorage 키: `korean-speaking-demo.v1.pronunciation` 첫 문장의 `모범 문장 듣기` 버튼 전체가 `320×844`에서도 스크롤 없이 보여야 한다. ## 2. 고정 학습 데이터 순서와 문구를 정확히 유지하라. ```js const ITEMS = [ { scene: '인사하기1', target: '안녕하세요.' }, { scene: '인사하기2', target: '만나서 반가워요.' }, { scene: '인사하기3', target: '안녕히 계세요.' }, { scene: '인사하기4', target: '안녕히 가세요.' } ]; ``` ## 3. 고정 저장 상태 ```js { index: 0, typed: '', attempts: [], completed: false } ``` `attempts`의 각 항목은 최소 다음을 저장한다. ```js { index: 0, spoken: '학생의 최종 인식 또는 입력 문장', score: 0, at: 'ISO-8601 문자열' } ``` ## 4. 초기 활동 화면 구조 위에서 아래 순서로 배치한다. 1. `1 / 4` 텍스트와 진행 막대. 2. 현재 장면 배지. 3. 현재 목표 문장. 개인 발음형이므로 처음부터 보여 준다. 4. 같은 행의 `모범 문장 듣기`, `천천히 듣기` 버튼. 5. 전체 폭의 주 행동 `내가 말하기` 버튼. 6. 레이블 `마이크가 어렵다면 직접 입력하세요`. 7. 한 줄 입력 필드. placeholder는 `들은 문장을 입력하세요`. 8. `입력 확인`, `다음 문장` 버튼. 9. `role="status" aria-live="polite"` 상태 영역. 10. 응답 후에만 보이는 결과 박스. 초기 상태 메시지는 `모범 문장을 먼저 들어 보세요.`다. ## 5. 상호작용 상태 전이 ### 듣기 - `모범 문장 듣기`: 현재 target을 `rate = 0.92`로 합성한다. - `천천히 듣기`: 현재 target을 `rate = 0.72`로 합성한다. - 듣기 후 상태 메시지는 `모범 문장을 듣고 같은 리듬으로 말해 보세요.`다. ### 말하기 - `내가 말하기`를 누르면 한국어 음성 인식을 시작한다. - 중간 인식값을 직접 입력 필드에 실시간 표시한다. - 최종 인식값을 현재 학생 응답으로 평가한다. - 인식 중에는 중복 시작을 막는다. ### 직접 입력 - 입력은 350ms 디바운스로 자동 저장한다. - blur와 pagehide 때 현재 DOM 입력값을 즉시 상태에 반영하고 저장한다. - 빈 값으로 `입력 확인`을 누르면 `문장을 입력한 뒤 확인하세요.`를 warn 상태로 표시한다. ### 응답 평가 - 공통 `scoreSpeech`로 target과 학생 문장을 평가한다. - 결과 박스를 열고 제목에 `${score}점`, 본문에 공통 점수 피드백을 표시한다. - 상태 영역에는 `인식 문장: ${spoken}`을 표시하고 피드백 tone을 적용한다. - 응답을 attempts에 추가한다. 같은 문장 재시도도 별도 attempt로 보존한다. - 현재 index의 attempt가 하나 이상 생기기 전에는 `다음 문장`을 disabled로 둔다. ### 다음과 완료 - 1~3번 문장에서는 응답 후 `다음 문장`으로 index를 1 증가시키고 typed를 빈 문자열로 만든다. - 4번 문장에서는 버튼 레이블을 `결과 보기`로 바꾼다. - 완료 상태에서는 다음을 정확히 표시한다. ```text 진행: 완료 배지: 연습 완료 본문: 카페 주문 문장 네 개를 모두 연습했어요. 결과 제목: 오늘의 기록 결과 본문: 총 N번 연습했고, 가장 높은 일치도는 B점이에요. 상태: 같은 표현을 실제 주문 상황에서도 사용해 보세요. 버튼: 처음부터 다시 보기 ``` - 완료 화면의 버튼을 누르면 기본 상태로 새 세션을 시작한다. ## 6. 하단 학습 팁 기본적으로 닫힌 details를 핵심 카드 아래에 둔다. ```text summary: 주문할 때 기억할 점 본문: 수량 + 주세요를 함께 말하면 자연스럽습니다. 문장 끝을 너무 올리지 말고 또렷하게 말해 보세요. ``` 그 아래에 공통 저장 상태, 기록 내려받기, 이 활동 초기화 컨트롤을 둔다. ## 7. 금지 사항 - 목표 문장을 숨기거나 단어별 애니메이션으로 쪼개지 마라. - 음성 인식만 제공하고 직접 입력을 제거하지 마라. - 다음 문장을 응답 전부터 활성화하지 마라. - 최고 점수를 서버로 보내거나 학습자 순위를 만들지 마라. - 녹음 파일을 만들거나 저장하지 마라. ## 8. 수용 테스트 1. 네 target을 직접 입력해 차례로 완료 상태까지 도달한다. 2. 부분 문장과 오답에서 각각 warn과 bad 피드백이 나오는지 확인한다. 3. 한 문장을 여러 번 시도하면 attempts가 누적되는지 확인한다. 4. 입력 직후 새로고침해 typed가 복원되는지 확인한다. 5. index 2와 일부 attempts가 저장된 정상 레코드를 주입했을 때 `3 / 4`로 복원되는지 확인한다. 6. 완료 레코드가 완료 화면으로 복원되는지 확인한다. 7. 잘못된 스키마 기록을 덮어쓰지 않는지 확인한다. 8. `320×844`, `390×844`, `720×450`에서 첫 듣기 버튼이 보이고 가로 스크롤이 없는지 확인한다.
